# DSS-ENGINE-C23-GCC-LINUX

**Deterministic Stochastic Storage Engine** — формально верифицируемый высокопроизводительный асинхронный NoSQL-движок хранения данных с дедупликацией на базе стохастического планирования.

## 🚀 Философия и Подход
Проект разрабатывается по методологии **Design by Specification** (Академическое проектирование). Математическая модель (Теория массового обслуживания, кольца многочленов Галуа, теория информации) первична. Код на Си — её строгое физическое воплощение.

## 🛠 Технологический стек
* **Язык:** Pure C23 (использование `_BitInt`, `typeof_unqual`, нативных логических типов).
* **Компилятор:** GCC 15+ (расширения `__attribute__((cleanup))`, интрузивные списки, векторизация SIMD).
* **ОС:** Linux (прямой асинхронный ввод-вывод через `io_uring`, `O_DIRECT`, `mmap`).
* **Архитектура ЦП:** System V AMD64 ABI (низкоуровневый ручной контроль фрейма стека).

## 📐 Математический фундамент
1. **Рантайм:** Моделирование планировщика как СМО (Системы массового обслуживания) типа M/M/1 и M/M/c для минимизации Latency Tail под нагрузкой.
2. **Дедупликация:**Content-Defined Chunking (CDC) на базе Rabin Fingerprints (вычисления в полях Галуа $GF(2)$) для оптимального разбиения потока данных на чанки.
3. **Память:** Индексация дубликатов через вероятностные структуры (Bloom Filter / Cuckoo Filter) с расчетом энтропии и минимизацией ложноположительных срабатываний ($P_{fp}$).

## 🗂 Архитектурный конвейер (Ментальная цепочка)
Каждый запрос проходит 4 изолированных слоя:
1. `facade_put` — Входной API, формирует сырые данные команды (`CmdData`).
2. `create_coroutine` — Выделение физического изолированного стека (`mmap`) и подготовка фрейма.
3. `create_task` — Создание паспорта задачи (метаданные, статус СМО, интрузивный узел) для Диспетчера.
4. `dispatcher_run_loop` — Сердце планировщика, управление очередями исполнения и асинхронным дисковым И/О.
