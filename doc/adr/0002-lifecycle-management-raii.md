# 2. Управление жизненным циклом ресурсов (RAII в Си)

* **Дата:** 25 июля 2026 г.
* **Статус:** Принято
* **Автор:** kshakirov

## Контекст
В кооперативном рантайме корутины динамически завершают свою работу внутри бесконечного цикла планировщика. Ручное освобождение дескрипторов задач, памяти стеков (`munmap`) и буферов данных чревато утечками памяти при усложнении логики обработки ошибок и нарушает детерминизм системы хранения.

## Решение
Использовать кастомное расширение компилятора GCC — атрибут `__attribute__((cleanup(cleanup_function)))` — для эмуляции деструкторов (RAII), появившихся в стандарте C23 на уровне концепций управления областями видимости.

Автоматическое уничтожение паспорта задачи и освобождение ассоциированного с ней стека локализуется строго внутри итераций `dispatcher_run_loop`. При выходе переменной задачи из области видимости (scope) текущей итерации планировщика, GCC автоматически вызывает деструктор.

## Последствия
* **Плюсы:**
  * Гарантированная зачистка ресурсов корутины без явных вызовов `free`/`munmap` в теле планировщика.
  * Код диспетчера избавляется от спагетти-кода очистки при обработке сбойных задач.
* **Минусы:**
  * Код становится зависимым от компилятора GCC (и Clang, поддерживающего этот атрибут).
