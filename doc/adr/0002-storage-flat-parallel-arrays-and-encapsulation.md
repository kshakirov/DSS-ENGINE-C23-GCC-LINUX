# 0003. Хранение индекса дедупликации: параллельные static-массивы

* Status: Accepted
* Date: 2026-08-22

## Context
Для работы алгоритма дедупликации необходимо сопоставлять хэши блоков с их адресами в памяти. На данном этапе ключевым требованием является максимальная локальность данных в кэше процессора (Cache Locality) и отсутствие прыжков по указателям (Pointer Chasing). Так как в C отсутствует встроенная хэш-таблица, а архитектура системы является однопоточной (кооперативная многозадачность на корутинах), необходимо выбрать структуру данных для хранения индекса.

## Decision
1. **Использовать структуру Parallel Arrays (Параллельные массивы):**
   - `static BlockHash blockHashTable[N];` — плотный массив хэшей для быстрого поиска.
   - `static BlockAddress blockAddressTable[N];` — синхронный массив адресов блоков.
2. **Инкапсуляция (Internal Linkage):**
   - Переменные состояния объявляются со ключевым словом `static` внутри модуля `storage.c`.
   - Публичный интерфейс модуля ограничивается внешними функциями (в частности, `process_file`). Прямой доступ к массивам из других модулей запрещен.
3. **Отказ от потокобезопасности:**
   - Так как система работает в одном ОС-потоке с явной передачей контроля через корутины (`yield`), блокировки (mutexes) не используются.

## Consequences
- **Positive:** Предельная простота, отсутствие накладных расходов (Zero Overhead), отличный utilization кэш-линий процессора при поиске.
- **Negative:** Вставка нового уникального хэша при отсортированном массиве имеет сложность $O(N)$ из-за сдвигов (`memmove`).
- **Mitigation:** Оформление взаимодействия с индексом через абстрактный интерфейс позволит в будущем бесшовно заменить внутреннюю реализацию на Open Addressing (Robin Hood Hashing) без изменений внешнего API.
