# Ассоциативная файловая система

DSS исследует файловую систему, в которой объект не обязан иметь единственное привилегированное местоположение в дереве.

Главная идея:

> Объект не обязан иметь единственное местоположение. Объект обладает множеством признаков, любой допустимый набор которых может служить способом его обнаружения.

## Не дерево и не "просто граф"

Цель не состоит в том, чтобы заменить дерево каталогов графом. Это изменило бы структуру связей, но сохранило бы старую идею адресации через положение объекта.

В DSS отделяются:

```text
идентичность объекта
```

и

```text
способ его обнаружения
```

## Path как частный случай

Путь остаётся допустимым:

```text
/books/math/lie/algebra.pdf
```

но он становится всего лишь одной ассоциацией наряду с другими:

```text
name = "algebra.pdf"
subject = "Lie algebra"
author = "..."
content_hash = ...
created_after = ...
```

То есть path не запрещается — он просто теряет привилегированный статус.

## Поиск как адресация

Вместо фундаментальной операции:

```text
path -> object
```

рассматривается более общий оператор:

```text
Q(P) -> { O1, O2, ... On }
```

где `P` — набор признаков или условие.

Следствие: поиск перестаёт быть внешней утилитой поверх файловой системы. **Поиск становится самой формой адресации.**

## Директория как сохранённый запрос

Каталог может быть не физическим узлом дерева, а представлением множества:

```text
D = { x | P(x) }
```

То есть "директория" может вычисляться как результат сохранённого запроса.

## Связь со storage

Ассоциативная модель не отменяет нижний блочный storage:

```text
Associative object model
        |
Associations / queries
        |
Object resolution
        |
Content
        |
CDC / Rabin
        |
Deduplication index
        |
Physical blocks
```

Ассоциативный слой решает, **как найти объект**.

Storage-слой решает, **как физически хранить его содержимое**, в том числе с CDC, Rabin fingerprints, дедупликацией и вероятностными фильтрами.

## Пока не фиксируем

На текущем этапе намеренно не определены:

- устройство ObjectId;
- язык запросов;
- обязательные типы ассоциаций;
- правила разрешения неоднозначности;
- формат персистентного ассоциативного индекса.

Сначала фиксируется семантическая модель, затем под неё выбираются физические структуры данных.
