# Архитектура Модуля Хранилища (Storage)

## Концепция сокрытия состояния
Модуль `storage.c` проектируется как инкапсулированный Singleton. Вся внутренняя структура данных изолирована с помощью `static` объявлений и не доступна для `main.c` или `dispatcher.c`.

### Структура памяти

[ storage.c (Internal Linkage) ]

┌──────────────────────────────────────────┐

│ static BlockHash blockHashTable[N]       │ 
──> (Хэши блоков)
│ static BlockAddress blockAddressTable[N] │ ──> (Указатели на блоки)

└──────────────────────────────────────────┘

▲

│ (Доступ только через API)

┌────────────────────┴─────────────────────┐

│        process_file(name, content)       │ ──> Public API

└──────────────────────────────────────────┘


## Эволюция структуры данных индекса
- **Текущая фаза (Прототип):** Parallel Arrays + Поиск. Реализует концепцию KISS и проверяет сборку.
- **Следующая фаза (Оптимизация):** Замена внутренней механики на Open Addressing (Robin Hood Hashing) под тем же публичным интерфейсом.
